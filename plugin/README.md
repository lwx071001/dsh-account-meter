# @local/account-balance — 安装说明

在**输入框下方那条统计带**里（内建 `stats` 药丸右侧）显示四个实时数字，并在**设置 → 账户与统计**
里提供一页开关与一份用量台账（分时 / 每天 / 每月曲线，总 token、平均每秒总 token、平均每秒输出
token、每百万与每千万 token 的金额；分时图可任选一天与时段）。

```
⚡ 12.3K tok/s · 缓存命中 88%        余额 ¥1,234.56 · 本对话 12.3K tok · 1m24s · 146 tok/s
└──────── 内建 stats（order 0）────┘ └──────────── 本插件（order 10）────────────┘
```

- **余额**：DeepSeek 账户可用金额（充值 + 赠送，按币种求和），点击刷新；
- **本对话 token 总量**：未命中输入 + 缓存命中 + 缓存写 + 输出；
- **运行时长**：对话**运行时计时、空闲时暂停**（真·秒表，见下）；
- **每秒 token**：token 总量 ÷ 运行时长。

悬停给出全部明细（含精确 token 数与计时状态）。

## 四个实时数字，四条来源，都是 Harness 自己的

### 1. 余额 → `account` Remote 命名空间

| 路线 | 结论 |
|---|---|
| `ctx.remote.account.getBalance(...)` → `@deepseek-ai/dsh-api-account-controller` → Host `ctx.deepseekAccount` | ✅ **采用**。这就是「设置 → 账户」页用的同一条路 |
| 用 `DEEPSEEK_API_KEY` 请求公开的 `GET https://api.deepseek.com/user/balance` | ❌ 不采用 |

`deepseekAccount` 的服务说明原文是 *"only Host consumers can obtain a request credential"* ——
取得 Platform 请求凭据是 Host 独占能力，账户控制器是唯一被授权这么做的组件。绕开会另立一套授权
判断，并在用户换 key / 登出后与真实登录态脱节。

**口径**：钱包 `balance` 是字符串小数；`value` 是充值余额、`bonusWallets` 是赠送余额，
两者**按币种分别求和**（赠送额度同样能花）。

### 2. token 总量 → 随包发布的 `tokenUsage` 投影

`@deepseek-ai/dsh-token-meter` 已注册该单元，把每个结算的 Assistant attempt 折成**四个互斥桶**，
同一 `(turn, step)` 的重复样本**替换**而非累加，并在 `llm/retry-started` 上关闭替换槽让重试只算一次：

```js
{ uncachedInputTokens, outputTokens, cacheReadTokens, cacheWriteTokens }
```

字段名本身就证明了互斥性：输入侧是三个 prompt 桶之和（内建 `StatsPills` 的
`billedInputTokens()` 正是这么算的），`reasoningTokens` 已含在 `outputTokens` 内。
所以**本对话总量 = 四者相加**。自己再 fold 一份会造出同一数字的第二份定义。

### 3. 运行时长 → 会话状态里的 `running`，客户端秒表

```js
const running = props.useSessionStatus(state => state.get(sessionId)?.running) === true
```

这个 `running` 就是已装包 Agent-Team 面板用来判断成员活动的那一个布尔值。计时器在它翻 true 时
开始、翻 false 时停止。

**为什么不用 `sessionStats` 的 `llmMs` / `toolMs`**：那两个只在**边界闭合时**累加（`llmMs` 记
`step/start → assistant/message`，`toolMs` 记 `tool/call → tool/result`），所以
① 它们无法实时跳动，② 被取消的 step 的耗时完全不进账。它们适合做"吞吐率"，不适合做"对话运行了多久"。

### 4. 输出速率 → `sessionStats` 的 `decodeMs` / `decodeTokens`

上一节拒绝的那份投影，这一项**正好要用**。这一对是同一台仪表的两项：`decodeMs` 从**首个流式 token**
量到消息装配完成，`decodeTokens` 是这些 step 上报的输出 token —— 所以**首字等待（prefill）、工具
执行、以及任何非输出 token 都不在这两项里**，相除出来的才是"写得多快"。

混用来源就会失真：拿 `tokenUsage` 的输出总量去除以这个时长，会把**从未被计时**的 token 算进来；
拿这里的 token 去除以对话运行时长，等于让模型为它没在写的时间买单。所以输出速率**只用这一对**，
而且**分子分母都来自它**。

```js
const stats = props.useProjection('sessionStats')     // 与已装 chat 面板同一个投影键
```

这不是自创口径：**内建 `StatsPills` 药丸算的就是这个式子** ——
`dsh-client-ui-chat/lib/client.js` 里 `stats.decodeTokens / (stats.decodeMs / 1e3)`，取的是同一个
`useProjection("sessionStats")`，拿的是同一个 slot prop。本插件的「平均每秒输出 token」是它的
**台账级平均**（跨已记录的全部会话），与那条实时药丸同源同法。

## 用量台账：分时 / 每天 / 每月

统计页把观察到的用量累进一份**三层汇总台账**（`localStorage`，键 `dsh.account-balance.usage.v2`）：

```
{ tokens, spend, activeMs,                    // 全时段累计（对话侧）
  outputTokens, outputMs,                     // 全时段累计（输出侧，provider 计时的解码段）
  inputTokens, cacheReadTokens,               // 全时段累计（提示词侧，供缓存命中率相除）
  seen: { <sessionId>: {tokens, ms, outputTokens, outputMs, inputTokens, cacheReadTokens} },
                                                // 每个会话"已经记过多少"
                                                //   null = 还不知道，与真实的 0 不同
  hours:  { '2026-03-09T14': {t, s} },        // 不限时，全部保留
  days:   { '2026-03-09':    {t, s} },        // 不限时，全部保留
  months: { '2026-03':       {t, s} },        // 不限时，全部保留
  balance, currency }                         // 上一次看到的余额基线
```

**第一次看见某个会话，只建立基线，不记任何用量。** 这是整份台账能成立的前提，也是 v2 存在的
理由：`tokenUsage` 与 `sessionStats` 都是**整份持久日志的累计值**，如果第一次读数就当成"新增"，
**打开一个旧会话的那一瞬间，它的全部历史会被记成"现在发生的"**。而金额永远只能来自**安装之后**
观察到的余额下降 —— 于是 token 列覆盖历史、金额列覆盖观察窗口，两者不可比。

修好之前，那份台账正是这样：`总 token` 是**整份历史**，`记录时长` 是**插件自己的秒表**（从第一次
看见该会话才开始走），`累计消耗金额` 是**观察到的余额下降** —— 三列三个窗口，于是
`平均每秒总 token` 和 `每百万 token 的金额` 都是"一个窗口除以另一个窗口"，数值再自洽也没有意义。
现在四列共用同一个窗口：**台账开始记录以来观察到的用量**（页面上直接写着这行说明）。

**增量记账**。台账记住每个会话**已经记过多少**，只把增量记进当前时段。没有这份记忆的话，
刷新页面会把整段对话的历史当成"刚刚发生"再记一遍。三种键都做零填充、定宽，所以**字符串排序就是
时间排序** —— 画图与日期选择器共用同一条排序规则，不需要解析日期。

**读数变小时重新定基，而不是记负数**。会话计数器可能因为 fork 或投影重置而回落；若沿用旧的
高点，之后所有增长都会被吞掉（台账纹丝不动而用量一直在涨）。所以**四个计数器各自独立地重新定基**：
token 回落不会丢掉同一读数里真实新增的运行时长，解码段回落也不会吃掉另外三个。
**读数缺失 = 保留原值**（不是当成 0）：把"投影还没发布"读成"解码段归零"，会在下一次推送时把
整段解码重新记一遍；同理，第一次读数缺失时存的是 **`null`（还不知道）而不是 0**，否则投影到达
时又会把整段历史当成新增。

**基线不落桶**：建立基线（或重新定基）时增量是 0，此时**不会**在时段里留下一个 `{t: 0}` 的空桶 ——
否则曲线上会凭空多出一个"那一小时消耗 0"的点。

**缓存命中率**用的是**内建药丸的口径**，不是自创：

```js
// dsh-client-ui-chat/lib/client.js
const billedInputTokens = usage => usage.uncachedInputTokens + usage.cacheReadTokens + usage.cacheWriteTokens
const cacheHitPercent = usage => formatCacheHitPercent(usage.cacheReadTokens, billedInputTokens(usage))
```

也就是 **缓存命中 ÷ 提示词侧**（未命中输入 + 缓存命中 + 缓存写），**输出 token 不计入** ——
`tokenBuckets()` 里的 `input` 字段就是 `billedInputTokens`，台账存的正是这一对。分母为 0 时返回
null（"没有可相除的提示词"），而不是一个自信的 0%。

显示上也照抄了官方那条**不肯凑整到 100%** 的规则：99.6% 显示为 `99.6%` 而不是 `100%`，因为
"几乎全命中"和"全命中"是关于计费的两个不同事实，而把两者混为一谈正好错在**会谎报一次没发生的
缓存命中**这个方向上。

> 这一对是**后加的**，所以旧 `seen` 记录里没有它们（读作 `null`）。这意味着缓存命中率的统计窗口
> 从升级那一刻开始，与总 token 的窗口有一段一次性偏差，随时间收敛。要一开始就完全对齐，按一次
> 「清空统计」即可（它会保留 `seen` 与余额基线，所以不会把历史重记一遍）。

**保留不限时，所以键的形状成了唯一的门**。以前靠"只留最新 N 个"顺手把垃圾一起裁掉；现在不裁剪了，
换由 `BUCKET_PATTERN` 逐字段校验键的形状（`YYYY-MM-DDTHH` / `YYYY-MM-DD` / `YYYY-MM`）——
读进来的键必须能是 `bucketKey` 写出来的，否则丢弃。没有这道门，一个畸形键会永远留在文档里。

**金额来自余额的减少量**。台账不猜单价 —— Harness 里不存在价格数据。它只观察账户余额：**降低**
记为消耗，**充值**只重设基线、绝不记负消耗，而**第一次读数只建立基线**（此前没有可比值，凭空记
一笔就是编造）。因此「每百万 token 的金额」是**实测等效单价**，而「每千万」就是同一口径放大十倍。

> 「赠送到期」与「换账号」目前**仍然会被记成一笔消耗**：前者是下降、后者币种没变，代码都不重设
> 基线，而这份余额载荷里没有足够信息把两者与真实用量区分开。已列入「已知限制」。

## 存储占用：把"不限时"的代价显示出来

保留不限时，代价就是这份文档会一直长。所以设置页底部直接给出实测占用：

```
统计台账      42.6 KB · 168 条
运行时长记录   3.1 KB · 42 条
显示偏好        96 B · 1 条
合计          45.7 KB
浏览器通常给每个来源约 5.00 MB 的配额，键与值都按 UTF-16 计费（每字符 2 字节）—— 当前约占其 0.9%。
```

几个刻意的选择：

- **实测，不是记账**。每次渲染直接枚举 `localStorage`，因为只有存储本身知道"每个会话一条的运行
  时长键"到底有多少条；用一个推算出来的计数迟早会和实际漂开（两者由不同代码、在不同时刻写入）。
- **按浏览器计费口径算**：`(键长 + 值长) × 2`。`localStorage` 存的是 UTF-16，配额也是这么扣的；
  本插件写进去的全是 ASCII（UUID、`YYYY-MM-DDTHH`、数字），所以"内容字节数"恰好是这个数的一半。
  要回答的是"离配额还有多远"，那就该用配额的口径。
- **空分组不显示**：`0 B · 0 条` 是噪音；`usage.v1` 只在从 v2 之前升级上来的机器上才存在。
- **写入被拒时会顶掉这一行**：配额满了以后 `setItem` 会抛异常，此前是静默吞掉的 —— 页面还在内存里
  继续记账，一刷新全没。现在这一行会变成橙色警告说明这件事，因为"不限时"让它成为真实终局而非假设。
- **曲线点太多时只丢悬停圆点，不丢点**：超过 `CHART_DOT_LIMIT`（120）个点就只画折线。圆点是悬停
  目标，挤成一团既读不出也不再可指；**数据一个都没少**，只是不再逐个画。

## v1 → v2 迁移

`dsh.account-balance.usage.v1` 的**数字含义**变了，所以键也跟着升级。读到旧文档时**不导入它的
总数**，只保留两样东西：

| 保留 | 为什么 |
|---|---|
| `seen`（每个会话"已经记过多少"） | 有了它，重设才不会把任何会话的历史**再记一遍** —— 它正是重设所需的那份信息 |
| 余额基线与币种 | 避免升级那一刻把当前余额整体记成一笔消耗 |

其余全部归零，与「清空统计」产出同一种形状、同一个理由：被丢掉的总数不是数据，而是一次**测量
误差的撤回**（旧文档仍在原键上原样保留，是那份 `seen` 的唯一副本）。

## 曲线图

手写 SVG，不引入任何图表库（纯 JS bundle 也没有可用的）：几何计算是纯函数 `chartGeometry`
（可从自测直接断言），颜色只用主题 token，每个数据点带原生 `<title>` 悬停提示。
三个页签切换分时 / 每天 / 每月。

**分时页多一组窗口选择器**：日期下拉（只列有记录的日期、最新在前、默认选最新那天）+ 起 / 止两个
小时下拉，图表只画这一天的这一段，窗口右侧直接给出**该段自己的合计**。日期与时段都是纯函数
（`hourDays` / `hourRangeEntries`），所以"能选什么"和"选了之后画什么"都能在自测里断言。
起止两端可以任意先后（取小者为起点），两个下拉显示的也是**排序后**的端点，所以标签不会和曲线
互相矛盾。

**每天 / 每月不加选择器，是总览**。也正因如此，下方那八项汇总**始终是全台账口径**：缩窄图表
不会悄悄改写下面的数字。

**"这一段没记录" ≠ "还没有记录"**：空曲线有两份文案，窗口选空时说"这一天的这个时段没有记录，
换一天或放宽起止"，而不是把读者引去怀疑记数本身没在工作。

**它不能渲染的点**：空系列不画点、全零系列不做除零、单点在正中、最大值恰好落在上沿。
**点太多时只丢悬停圆点**（超过 `CHART_DOT_LIMIT` 就只画折线）：保留不限时，长期台账一定会走到
那一步，数据一个都没少。

## 与 liquid-glass 皮肤保持一致

`dsh-liquid-glass`（同一 profile 的皮肤插件）给输入框下方这排指标套了一层玻璃胶囊，但它**按位置**
找目标 —— 选择器是 `[data-slot='conversation.composer.dock'] > :first-child`，命中的是内建 `stats`
（order 0）。它自己的注释把这条规则叫作 "StatsLine"，也就是说它假定这个 dock 里**只有一个** occupant；
本插件注册的是第二个（order 10），于是这一行**光秃秃地贴在属于同一行文字的胶囊旁边**。

所以本插件**镜像**了这层胶囊，作用域与它**同源**（`body[data-dsh-liquid-glass]`），并且**读同一批
`--lg-*` 变量**。这样两件事同时成立：

- 皮肤关掉时这条规则完全不生效，本行与邻居一样朴素 —— **两种状态都一致**；
- 皮肤自己的设置（模糊、着色、圆角）一改，两个胶囊**一起动**，而不是分叉。

**刻意不镜像的四条**：`height` / `overflow` / `text-overflow` / `white-space`。皮肤用它们截断一条
不能换行的文字，而本行是**会换行自己的格子**的设计 —— 把余额的尾数裁掉比多出一行更糟。

**同一排最右边那个上下文占用的圈也一样。** 它在一层之外：官方 composer 把它渲染成 dock anchor
（那个 `display:contents` 的 `[data-slot=...]` 容器）的**兄弟节点**，而不是 dock 里的一个 occupant，
所以按位置找 occupant 的那条皮肤规则同样够不到它。本插件用**兄弟关系 + 控件角色**定位它 ——
`[data-slot='conversation.composer.dock'] ~ * button[aria-haspopup='dialog']`：不依赖官方模块里那些
每次构建都会变的哈希类名，也不必知道它的内部结构。胶囊套在**按钮**上而不是外层包裹上，理由和皮肤
自己处理 `sidebar.settings` 一样：内边距、hover 与 aria 状态都在按钮上。

它是那一排里唯一会打开面板的胶囊，所以**额外把 hover 与展开态还回去**（边框换成
`--lg-border-strong`，并保留内高光）。不这样做的话，这条规则的高优先级会把原生那条 hover 填色顶掉，
点击前的反馈就没了 —— 把交互控件"装扮"成装饰，是这类镜像最容易踩的坑。

**唯一没覆盖的是新会话的 hero 视图**：官方在那里根本不渲染 dock anchor，够到它就得写哈希类名或去猜
它的包裹层；而那个视图里本插件自己那一行也不渲染，没有需要对齐的对象。

重复声明本身就是风险，所以自测里有一条**防漂移**断言：只要 `liquid-glass` 的源码在旁边，就把那条
规则的 13 条共享声明与**本插件的两个胶囊**逐条比对，它一改就直接失败。

> 根因在那个选择器里，不在本插件：`> :first-child` 是"只有一项"的代理写法。若更愿意从源头修，
> 把 `liquid-glass` 的 `src/client/css/cards.js` 里 `> :first-child` 改成 `> *`，所有 occupant 就都会
> 被覆盖，本插件的镜像规则可以随之删掉。这里选择镜像，是为了**不改别人的插件**，也不让那条规则去
> 影响将来可能注册进这个 dock 的其它内容。

## 为什么设置项不用官方那条路

官方做法（`ui-conversation` 的「Composer Enter」就是）是：宿主半用 `@deepseek-ai/schemastery`
声明 `Config`，客户端用 `ctx.configForms.get(命名空间)` 读写，值落进用户设置文档。本插件**没有**走这条路：

- `@deepseek-ai/schemastery` 住在 `app.asar` 内，profile 的 `node_modules/@deepseek-ai` 是空的，
  纯 JS bundle **无法解析**它（`ctx.configForms` 也不在客户端 Service 目录里，只能 `ctx.get()` 软取）；
- 宿主半一旦有真实模块，改浏览器半就从"刷新页面"变成"**重启 Harness**"。

所以显示偏好与用量台账都放在浏览器 `localStorage` —— 与同 profile 里的 `theme-studio` 完全一致的选择。
设置页**本身**仍走官方 UI 位置 `settings.section`（`order: 13`，在 Models 10 与 Plugins 15 之间），
所以观感与其他设置页一致。

## 设置页

**设置 → 账户与统计**（`settings.section`，`id: account-balance`）：

| 分组 | 内容 |
|---|---|
| 显示内容 | 总开关「显示状态行」+ 四个明细开关（余额 / token 总量 / 运行时长 / 每秒 token） |
| 用量统计 | 分时 / 每天 / 每月页签 → 分时窗口选择器 → 曲线图 → 八项汇总 → 清空统计 |
| 存储占用 | 台账 / 运行时长 / 旧版台账 / 显示偏好各自的实测大小与条数，加合计与配额占比 |

汇总八项：**总 token**、**记录时长**、**平均每秒总 token**、**平均每秒输出 token**、**平均缓存命中率**、
**累计消耗金额**、**每百万 token 的金额**、**每千万 token 的金额**。前几项的分母写在旁边的说明行里：
总速率除以 **运行时长**，输出速率除以 **provider 计时的解码时长**，缓存命中率除以 **提示词侧 token**。

四个明细开关在总开关关闭时置灰禁用。「清空统计」是两步确认（4 秒后自动解除），清空后保留
`seen` 与余额基线，所以是"从现在重新计"，而不是把当前对话历史再记一遍。显示开关的改动**即时生效**：
状态行与设置页共用同一个快照 store。

## 实时性

| 数字 | 机制 |
|---|---|
| token 总量 | **推送**（投影注册表），无需轮询 |
| 运行状态 | **推送**（会话状态 store），无需轮询 |
| 运行时长 | 运行中每秒 tick 一次；空闲不动 |
| 余额 | **轮询**：成功 60s、失败退避 15s；页面重新可见 / 获得焦点时立即读；点击立即读；`document.hidden` 时跳过 |
| 台账写入 | 只在台账**真的变化时**写一次，且每秒最多一次（依赖用秒级量化值，不是毫秒时钟） |

同一时刻只允许一个在途余额请求；读失败时**保留上一次数字**并转为警示色，悬停里说明原因。

## 配色：一套颜色家族，靠字重分主次

标签与 `·` 分隔符用 `--dsw-alias-label-tertiary`（环境文字），**四个数字共用**
`--dsw-alias-label-secondary` 加 `font-weight: 500`。数字与标签的区别由**字重**承担而非色相，
所以一行四个数字也不会显得像四个各自为政的小组件。

状态色（`state-warn` / `state-error`）**只作用于余额那一格** —— 早期版本把 tone 类挂在根节点上，
余额读取失败会把 token 数字一起染成琥珀色。设置页沿用宿主设置页的排版语汇：`.ab-page` /
`.ab-group` / `.ab-row`（`.5px solid --dsw-alias-border-l1` 行分隔）/ 圆角 `--dsw-radius-md` 药丸按钮；
曲线用 `--dsw-alias-brand-primary`，坐标轴用 `--dsw-alias-border-l2`。

## 安装（在当前 profile，一次性，永久生效）

```
plugin_manager  action: install_bundle   target: F:\CaelumProject\dsh\account-balance\plugin
```

安装器负责 pnpm 安装、选入 `dsh.profile.bundles`、接入 bundle 自带的 patch 行 —— **不要**手写
profile 的 `package.json` / `cordis.patch.yml`，也不要在 profile 目录里跑 pnpm。也可以走侧边栏
**Plugins** 页面「添加」。

**本插件已装在本机**（profile `desktop`），并且是 **link** 安装。

## 安装后核对

1. `install_bundle` 返回里 `application: "applied"`、`warnings: []` 才算生效。
2. `cordis_inspect_query`（`Config.listConfigs`，`name: "@local/account-balance"`）→
   `include:account-balance` 行在组合树里。
3. `cordis_inspect_query`（Client `Slots.listSubTree`，`root: "conversation.composer.dock"`）→
   occupant 里有 `{ id: "account-balance", order: 10, active: true }`。
4. 同上查 `root: "settings.section"` → occupant 里有 `{ id: "account-balance", order: 13, active: true }`。
5. 页面确认：统计带里出现四个数字；设置里出现「账户与统计」页，含页签、分时窗口选择器、曲线、八项汇总与存储占用。

> **改 `client.js` 后必须刷新页面**：浏览器半在页面启动时按 `window.__DSH_BOOT__` 拉取注册，
> 运行中的页面不会自己换代码。宿主半若改动才需要重启 Harness。

## 卸载 / 停用

- 停用：`plugin_manager` `set_bundle`（整包）或 `set_plugin`（单行）置 `enabled: false`。
- 卸载：`plugin_manager` `remove_bundle`。
- 槽注册与词典都是 `apply` 上下文的 effect，停用即消失；组件卸载时 `<style>`、定时器、
  `focus` / `visibilitychange` 监听一并清除。
- 遗留的 `localStorage`（`dsh.account-balance.*`）不会被清除；需要的话手动删。

## 已知限制

- 余额是 Platform 钱包读数，**不是**按单价推算的账单；金额一律来自余额的实际减少量。
- **无法解析的钱包金额会被丢弃**（`parseMoney` 只接受十进制字符串）。因此"已登录、`status: ready`、
  但一个可读钱包都没有"是真实结果，此时显示「无可读余额」并给出说明，而不是留在"读取中…"上 ——
  那是个不会自行解析的标签。
- token 总量是 provider 计数（四个互斥桶之和），**不含子代理 / 工作流**的 token。
- **台账只覆盖本浏览器开始记录以来的时段**：页面关着时对话在跑，那段的 token 与扣费都不会被记录。
  总额与曲线因此是"已观测"而非"账单全量"。（余额侧的追认是准的：基线会持久化，重新打开页面后
  第一次读数会把离开期间的整体下降一次记清。）
- **赠送额度到期会被记成一笔消耗**。赠送额度是下降、币种没变，代码不重设基线；而这份载荷里
  只有 `{currency, balance}`，没有到期时间、没有授予 id，**无法把"到期消失"与"被用掉"区分开**。
  要彻底解决只能只统计充值钱包的下降，那又会让"用赠送额度跑"的时段金额恒为 0。两条路都不完美，
  所以先把已知误差写在这里。
- **登出后换账号也会被记成一笔消耗**（币种没变时基线不重设），充值场景同理不会记负数。
- **换币种会把金额整体重新计**：目前 `spend` 是单一累加器，币种变化时只换基线、不换算金额。
  币种实际发生切换时，请按一次「清空统计」。
- **运行时长是"高水位线"**：`writeDuration` 永不写入比已存值更小的数字，因为时长只会累积 ——
  更小的数只可能是旧值。离开时（切会话 / 关标签页 / 刷新）正在跑的那一段会**现场重算并写回**，
  所以不会再出现"切走再切回来，计时器倒退几秒"。
- 台账挂载在会话输入框下方那条状态行上，所以**隐藏状态行不会停止记账**，但**切到非会话面板**
  （如设置页）期间的增量会在返回时被并到当时的时段里 —— 影响的是时段分布，不是总额。
- 运行时长、显示偏好与用量台账都存在**当前浏览器**的 `localStorage`，不进 profile、不跨浏览器同步；
  清站点数据会丢。
- **输出速率只统计 provider 计到时的解码段**：被取消的 step 不装配消息，那段流式时间不进 `decodeMs`，
  所以它衡量的是"已完成输出的速度"。分子分母同源，比值自洽，但它不是"已产出 token ÷ 全部生成时间"。
- **保留不限时，所以文档会一直长**：读进内存后每次提交都会整份 `JSON.stringify` 并写回，随时间
  线性变贵。设置页的「存储占用」就是为此存在；配额写满后 `setItem` 会抛异常，那一行会变成橙色
  警告说明"此后只在本页内存里记账"。
- **分时窗口不再有保留窗口限制**：日期下拉会列出**所有曾经记录过的日期**，随时间线性变长。
- **v1 → v2 迁移会清空旧总数**（原因见上）。旧文档仍在 `dsh.account-balance.usage.v1` 上原样保留，
  需要的话可以人工比对。
- 新会话还没跑过请求时 token 显示 `—`；运行不足 1 秒不产生速率（避免首秒虚高），解码段不足 1 秒
  同样不产生输出速率。
- 渲染位 `conversation.composer.dock` 是 `scope: session`，无会话的页面不显示。

## 验证

```
node ../tools/check-bundle.mjs     # 592 项断言
```

十三层：**执行**（两个半真实 import，只打桩 `window`；并且**整文件编译一次**，所以 factory 里的
语法错误也会在这里失败，而不是在浏览器里变成一个空槽）、**清单**（exports / patch / 图标 / i18n）、
**金额运算**、**时长/速率/偏好**（含速率格式化器在 10–1000 区间不得输出长小数）、
**缓存命中率**（与内建 `billedInputTokens` 口径同源、输出不计入、分母为 0 时无值、不许凑整到 100%）、
**用量台账**（键的零填充与可排序性、不裁剪、**键形校验成为唯一的门**、增量只记差额、
**第一次读数只建立基线**、迟到投影不会变成一堆假历史、六个计数器各自回落重新定基、
"读数缺失≠归零"、基线不落空桶、余额只把减少记为消耗、逐字段容错回退）、
**v1 → v2 迁移**（总数与曲线被撤回、`seen` 与余额基线被保留、迁移后不再重复记账、
v2 记忆里的提示词对读作未知、损坏的旧文档不抛异常）、**存储占用**（分组归属、按 UTF-16 计费、
外键不计入、空分组、不可读的存储返回 null 而非 0、单位换算、配额占比、写入被拒会亮旗）、
**余额格子分支**（六个分支各自断言，"已登录但无可读钱包"是其中之一）、**解码段**（两项同源、
缺投影读作 null、脏值回退）、**运行时长记录**（高水位线：更小与相等的值都被拒绝、小数先取整、
空会话 id 不写、损坏记录读作 0；离开时现场重算并写回）、**分时窗口**（日期列表最新在前、
时段两端皆含、反向端点等价、无匹配为空、区间合计只算自己那段）、**曲线几何**（最大值落上沿、
单点居中、全零不除零、折线点串）、
**配色不变量**、**词典**（含 `{}` 占位符替换）、**渲染冒烟**（用最小 React 替身把两个组件各渲染
一次并遍历文本：标签、**数字**、空分组、缺少可选 hook prop 时的降级）、**玻璃胶囊镜像**（把本插件
镜像的 13 条声明与 `liquid-glass` 源码里的那条规则**逐条比对**，两个胶囊各比一遍，并断言四条刻意
省略；另断言上下文圈是用兄弟关系 + 控件角色定位、且 hover 与展开态仍在）。

> **渲染冒烟**是最后补的一层，因为前面所有断言都只验证纯函数 —— 而用户**看到**的一切都经过组件，
> 组件里崩掉只会让整页空白，离线断言一个字都不会说。这一层验证过**有牙齿**：故意改错
> `StorageSection` 的一个 `labels` 键，它立刻报 `the rendered settings page shows "统计台账"`。
>
> **玻璃胶囊镜像**那条断言是"防止重复声明漂开"的：这类跨插件的复制粘贴靠人工维护一定会腐坏，
> 所以让它在腐坏的那一刻失败。

**它不能证明渲染正确**。视觉与交互需要连接中的浏览器页面，按上面「安装后核对」第 3–5 条确认。
